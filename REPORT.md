# Big Catch · 20.1

Самостоятельный бесплатный офлайн-продукт для iPhone и iPad, iOS 17.6+. Xcode-проект: `Nacre.xcodeproj`, общая схема `Nacre`, конфигурации `Estuary` и `Tidal`. Нет сторонних зависимостей, аккаунтов, аналитики, рекламы, покупок или сетевых API.

Реализовано: заброс, ожидание поклёвки и окно подсечки; вываживание с натяжением и возможностью немедленно ослабить леску; четыре открываемых озера, двенадцать видов с таблицами по времени устройства и уровню приманки; коллекция с количеством, личными рекордами и последними уловами; три удилища и три приманки за игровые монеты, покупка и выбор; опыт открытия озёр; припасы по timestamp каждые пять минут с лимитом восемь часов; ежемесячные цели и постоянные памятные бейджи; локальное сохранение с резервной предыдущей записью, единицы веса, тактильный отклик, спокойный режим, удаление данных с подтверждением. Уловы создаются только после успешной игры, затем рыба возвращается в воду.

Виджеты: small с игровым клёвом по времени суток; medium с прогрессом следующего озера; large с коллекцией, озёрами и сезонной целью; Lock Screen inline/circular/rectangular с часами клёва. WidgetKit читает общий локальный снимок, использует почасовой timeline и deep links. В настройках доступен предпросмотр тех же представлений из реальных локальных данных. EN, DE, FR, PT-BR: UI, каталог InfoPlist и ASO в `Store/metadata.json`. Иконка и пейзаж созданы image_gen; промпты и визуальная проверка — `Art/prompts.txt`.

Решения по SDK: требование виджетов реализовано отдельным обязательным WidgetKit extension; два дополнительных target существуют только для QA. В сдаче шесть авторских Swift-файлов, из них один тестовый; общий код компилируется в приложение и extension. Live Activity и NSSupportsLiveActivities не заявлены, поскольку индивидуальное ТЗ прямо исключает Live Activity и здесь нет соответствующего процесса. Неиспользуемые privacy-разрешения не объявлены. App Groups и Push Notifications объявлены в entitlements, UIBackgroundModes содержит только remote-notification по регламенту. APNs не регистрируется, внешних пушей и серверов нет; все напоминания — UNCalendarNotificationTrigger после добровольного включения. Подпись, регистрация App Group и push entitlement в аккаунте разработчика потребуются для установки на физическое устройство.

Первичные источники Apple, проверены 15.11.2026:
- [WidgetKit strategy](https://developer.apple.com/documentation/WidgetKit/Developing-a-WidgetKit-strategy): extension и общий App Group.
- [TimelineProvider](https://developer.apple.com/documentation/widgetkit/timelineprovider/): снимки и timeline без постоянного фонового процесса.
- [Scheduling local notifications](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app): системное локальное расписание без своего сервера.
- [Required reason API categories](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitype): основания CA92.1 и 1C8F.1.
- [UserDefaults](https://developer.apple.com/documentation/foundation/userdefaults): общий suite и privacy manifest. Причины CA92.1 и 1C8F.1 указаны для собственных настроек и App Group.

Артефакты: `Build/BigCatch-unsigned.xcarchive` — неподписанный Release arm64; `Build/BigCatch-simulator.app` — локальная simulator-сборка. Build/DerivedData и QA-логи отделены от исходной поставки. Публикация и отправка в App Store не выполнялись.

Проверено 15.11.2026: simulator BUILD SUCCEEDED; device arm64 ARCHIVE SUCCEEDED; ad-hoc TEST BUILD SUCCEEDED для обоих тестовых target; 412 проверок общей Foundation-логики (`QA/core-rules.json`); валидные plists и privacy manifest; полные четыре локали; отсутствие запрещённой лексики в UI/ASO и личных путей в исходниках и во всех файлах Release-архива. Аудит `QA/audit.json` подтверждает шесть Swift-файлов, 74 свежих UUID и отсутствие пересечений с доступными проектами линейки. Локальная ad-hoc подпись приложения и расширения проверена: общий App Group присутствует в обоих entitlement-наборах. Иконка непрозрачная, 1024×1024.

Ограничение окружения: `QA/run_pool.py` запущен, но более 40 минут ожидает общую блокировку simulator_pool. На момент передачи ни iPhone, ни iPad не выделены. Выполнение UI-тестов, отрисовка виджетов и локализаций на устройстве, отказ в уведомлениях и визуальная проверка снимков НЕ подтверждены. Готовый сценарий остаётся в штатной очереди и обновляет `QA/STATUS.md` и `QA/native-status.json` после каждого устройства. Результаты появятся в `QA/phone.xcresult`, `QA/pad.xcresult`, PNG-снимках и `*-shared-state.json`; скрипт обновит пакет исходников. Визуальную приёмку PNG необходимо выполнить после их появления. Чужие устройства и процессы не изменялись, блокировка не обходилась. Прямой read-only запрос inventory через xcrun был отклонён auto-review; затем использован разрешённый API штатного пула, а весь foreground-скрипт запускается только через helper.

Вне локальной проверки: provisioning на физическое устройство, доставка уведомлений по реальному системному расписанию, регистрация App Group/Push в аккаунте Apple, размещение и ревью App Store. Это не выполнялось. Пуш-сервера нет по проекту, APNs-доставка не заявляется.

Исходная поставка: `Build/BigCatch-source.zip`, без DerivedData, xcuserdata и системных логов. Повторный QA: `python3 QA/run_pool.py` в окружении фабрики; скрипт выбирает существующие шаблоны и вызывает штатный `simulator_pool.py TEMPLATE_UDID bash QA/qa.sh`. Для повторного прогона нужны новые имена resultBundle либо перенос старых xcresult; существующие симуляторы не стираются.
